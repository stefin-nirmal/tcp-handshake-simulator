Sequence & Acknowledgment Numbers

Math & Arithmetic
Client Initial Sequence Number (ISN)
Seq = 1000

Generated randomly by client OS to prevent packet collisions and replay attacks.

Server Initial Sequence Number (ISN)
Seq = 5000

Generated independently by server OS for the return byte stream channel.

Step Packet Sender → Receiver Sequence (Seq) Acknowledgment (Ack) Calculation Rationale
1 SYN Client → Server 1000 - Client proposes starting byte at 1000.
2 SYN-ACK Server → Client 5000 1001 Ack = 1000 + 1 (Acknowledge client's SYN, which consumes 1 sequence number).
3 ACK Client → Server 1001 5001 Ack = 5000 + 1 (Acknowledge server's SYN, which consumes 1 sequence number).
💡
Why do the Acknowledgment Numbers increase by +1?

In TCP, even though a pure SYN or FIN control segment carries 0 bytes of application user data, RFC 793 defines that SYN and FIN control flags logically consume exactly one sequence number. Therefore, the receiver must increment the acknowledgment by 1 (i.e., Ack = Seq + 1) to confirm receipt of that control flag.

📚 Educational Concepts & Reference

Core theoretical fundamentals for Computer Networks lab demonstration and viva

What is TCP?

TCP (Transmission Control Protocol) is a connection-oriented transport layer protocol that provides reliable, ordered, and error-checked delivery of a stream of octets (bytes) between applications running on hosts communicating via an IP network.

  • Connection-Oriented: Requires establishing a session before data exchange.
  • Reliable: Uses acknowledgments, retransmission timers, and sequence numbers.
  • Full-Duplex: Both client and server can transmit data concurrently.

What is the Three-Way Handshake?

The Three-Way Handshake is the process TCP uses to establish a reliable connection between two communicating endpoints. It synchronizes sequence numbers, exchanges initial parameters, and allocates internal socket buffers and variables on both sides.

  • Step 1: SYN (Synchronize sequence numbers)
  • Step 2: SYN-ACK (Synchronize + Acknowledge)
  • Step 3: ACK (Acknowledge server response)

2. SYN-ACK — Synchronize + Acknowledge

Server → Client | Flags: SYN = 1, ACK = 1

The server responds with SYN-ACK. It acknowledges the client's request and sends its own synchronization request.

Server State: SYN-RECEIVED Client State: ESTABLISHED

3. ACK — Acknowledge

Client → Server | Flags: SYN = 0, ACK = 1

The client sends an ACK to confirm the server's response. The TCP connection is now established.

Both Hosts: ESTABLISHED Status: Ready for Data Transfer
Key Viva Question

Why does TCP require a Three-Way Handshake instead of just Two steps?

Because TCP is a bidirectional (full-duplex) connection, each host must establish its own initial sequence number and receive explicit acknowledgment from the other side:

  1. In Step 1 (SYN), the client communicates its sequence number.
  2. In Step 2 (SYN-ACK), the server acknowledges the client's sequence number and communicates its own.
  3. In Step 3 (ACK), the client acknowledges the server's sequence number.

If only two steps were used, the server would never know if the client received its sequence number, and old delayed duplicate packets wandering the network could cause the server to mistakenly open zombie connections!
